# Phase 260723-91v Plan 01: Make Vendor Personnel Tab Sole Owner (Stop Edit-PUT From Sending Personnel) Summary

Stopped EditContract's and CreateMSADialog's edit-mode PUT payloads from including a `personnel` field, so the dedicated Vendor Personnel tab (shipped in `6cd5433f2`) is the sole writer of vendor personnel data — editing a contract or MSA through the monolithic form can no longer clobber personnel already saved via the dedicated tab.

## What Changed

**`EditContract.tsx`** (edit-only component, no create path lives here):
- Removed the `personnel` computation block (`const personnel = ...` derived from `data.personnelMeta`/`data.personnel` via `toPersonnelOrUndefined`).
- Removed the `personnel,` line from the returned `payload` object in `buildPayload`.
- Removed the now-orphaned `toPersonnelOrUndefined` import (confirmed via grep it had no other usages in the file).

**`CreateMSADialog.tsx`** (shared `buildPayload` for both create and edit):
- Left the `const personnel = ...` computation untouched (still needed for create).
- Changed the payload key from `personnel,` to `personnel: isEditing ? undefined : personnel,` — gated on the existing in-scope `isEditing` boolean.
- Confirmed by reading `src/lib/pruneEmptyValuesDeep.ts` that its object-pruning branch (`if (cleaned !== undefined) next[k] = cleaned`) omits any key whose value resolves to `undefined`, so the edit-mode PUT body has no `personnel` key at all (not `personnel: undefined`). No additional key-deletion logic was needed.

## Verification

- `npx tsc -b` — clean, zero errors, after both changes.
- Grep confirms `EditContract.tsx`'s `buildPayload` return object no longer assigns a `personnel` key (the one remaining `"personnel"` grep hit at line ~1062 is an unrelated step-field-name list used for step validation, not the payload).
- Grep confirms `CreateMSADialog.tsx`'s `personnel` payload key is now gated on `isEditing` (line ~953: `personnel: isEditing ? undefined : personnel`).
- No changes made to `CreateContractSheet` or to any create-only code path — contract create and MSA create (`isEditing === false`) continue to send `personnel` exactly as before.

## Deviations from Plan

None — plan executed exactly as written. The `pruneEmptyValuesDeep` behavior was confirmed by reading the helper (as instructed) rather than assumed; no fallback key-deletion was required since the helper does strip undefined values from plain objects.

## Known Gaps (documented in plan, intentionally deferred)

The Step 2 personnel chips UI in both `EditContract.tsx` and `CreateMSADialog.tsx` (edit mode) still render and remain editable, but any changes a user makes there during edit are now silently discarded on save (the payload no longer carries them). A follow-up task should make these chips read-only or hidden during edit and redirect users to the dedicated Vendor Personnel tab. This gap is called out in `.planning/STATE.md` under Blockers/Concerns and should be resolved by a future quick task before this is fully user-facing-safe.

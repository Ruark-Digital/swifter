# Phase 260723-0y0 Plan 01: Prune dead approver/viewOnly redline-suggestions endpoints Summary

Removed the `isApprover`/`isViewOnly` branches from `buildEndpoint` in `useAiRedlineSuggestions.ts` since the BE (docs.json v2.3.0) no longer exposes the `/approver/...` and `/user/...` AI redline-suggestions routes — only `manager` and `vendor` (vendor + projectManager) variants remain live.

## What Changed

- `buildEndpoint` now takes only `documentId`, `isMsa`, `isManager`, `isVendor`, `isProjectManager` — the `isApprover`/`isViewOnly` params and their branches were deleted, so those roles fall through to the existing `return null;`.
- The call site in `useAiRedlineSuggestions` no longer passes `isApprover`/`isViewOnly` into `buildEndpoint`.
- Updated the JSDoc above `useAiRedlineSuggestions` to document only the manager/vendor live endpoints and note that approver/viewOnly resolve to `url=null`, which the pre-existing `mutationFn` null-url guard turns into a benign `{ summary: "", riskLevel: "low", overallSuggestion: "accept", suggestions: [] }` result (no network call, no 404).
- `isManager` and `isVendor || isProjectManager` branches are unchanged (same URL strings produced).
